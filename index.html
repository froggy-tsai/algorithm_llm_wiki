02 · 比較排序的限制

只靠兩兩比較，最壞情況需要多少比較？

決策樹的每個內部節點代表一次比較；分支記錄比較結果。若有 n 個互異元素，就有 n! 種排列需要區分。

葉節點數量

高度為 h 的二元樹，最多有 2h 個葉節點。

2h ≥ n!　⇒　h ≥ lg(n!)

漸進下界

利用 n! ≥ (n/e)n：

h = Ω(n lg n)

適用範圍：此下界限制比較排序。Counting sort 不比較元素，Radix sort 逐位使用穩定排序，並不違反這個下界。

來源：L5《Sorting Lower Bounds》投影片 2–10、28–29；Wiki：比較排序的決策樹下界。
03 · 比較排序

插入排序：把新元素插入已排序前綴

每一輪取出 key，從右向左比較；比 key 大的元素右移，再把 key 放入空位。

最壞情況
Θ(n²)
平均情況
Θ(n²)，假設所有排列等可能

教材指出已排序輸入較容易處理，但本講義未列最好情況的明確 Θ 表達式。

來源：L1 投影片 5–23；Wiki：插入排序、演算法分析。
04 · 比較排序

Merge sort：分成兩半，再合併

Divide：切分序列。Conquer：遞迴排序兩半。Combine：線性時間合併已排序序列。

T(n)=2T(n/2)+Θ(n)　→　Θ(n lg n)
來源：L1 投影片 24–50；L3 投影片 3–6；Wiki：Merge sort、遞迴式與遞迴樹。

06 · 比較排序

Quicksort：pivot 如何切分？

選 pivot，將元素分到 pivot 兩側，再遞迴排序兩邊。

最壞情況
Θ(n²)，例如首元素 pivot 遇到已排序輸入。
Randomized quicksort
期望 O(n lg n) 上界；分析假設元素互異、隨機選擇獨立。
來源：L4 投影片 2–47；Wiki：Quicksort。
07 · 非比較排序

Counting sort：先計數，再定位輸出

適用於鍵值在 1..k 的輸入。累積計數提供輸出位置；從右向左填入可維持相同鍵值的原始相對順序。

Θ(n+k)；若 k=O(n)，則為線性時間。

來源：L5 投影片 11–30；Wiki：Counting sort。
08 · 非比較排序

Radix sort：由最低位逐趟排序

每一趟使用穩定排序，讓較低位已建立的次序不被破壞。

Θ((b/r)(n+2r))

線性時間結論取決於位數、每趟基數與鍵值範圍等條件。

來源：L5 投影片 31–39；Wiki：Radix sort。
